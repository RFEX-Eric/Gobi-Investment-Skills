# Research Studio 产品手册

给投研团队的简明说明：如何开始研究、共同讨论，以及把资料留给下一次研究。

最后更新：2026 年 10 月 16 日。**本版让行业研究按目标选择：快速建立认知、回答具体问题、完整深度研究。** 核心判断首页对应这次目标，正文补充解释，并给出待团队讨论的初步投资框架。左侧仍先展示四个团队 Skill 和行业知识库，再展示项目；“新建项目”固定在顶部，原有团队入口、项目、资料和报告保留。

本手册对应 2026-10-16 第 30 版。团队入口由管理员私下提供；本公开包不附带访问凭证。下面的使用说明描述现有产品，新部署须另行配置。

## 1. 按什么顺序使用？

**新建项目在哪里？** 左侧顶部有醒目的“＋ 新建项目”，团队首页和右上角也有入口。创建后即可上传资料；项目会自动加入当前团队，同事不需要新链接。

| 左侧入口 | 在这里做什么 |
| --- | --- |
| ＋ 新建项目 | 创建团队项目，作为本次研究资料、任务和报告的归属 |
| 团队 Skills：行业研究 | 查看团队已有行业研究，或开始一份新的行业报告 |
| 团队 Skills：Company Mapping | 查看团队已有公司梳理，或主动寻找、归类和初筛公司 |
| 团队 Skills：技术投资手册 | 查看团队已做的公司技术研究，或深入研究一家公司 |
| 团队 Skills：公司对比 Dashboard | 查看相关尽调任务和报告，或继续比较公司、更新共享看板 |
| 行业知识库 | 按行业查看过去成果、来源和积累的认识；也可发起公开学习 |
| 具体项目列表 | 回到某个项目，上传资料、阅读报告、查看协作动态 |

**找过去的研究，直接点 Skill。** 例如进入“行业研究”，就能看到团队不同项目下的电子皮肤、RSI、世界模型等相关任务，不用先逐个打开项目。默认展示全部项目，可搜索或按项目、任务状态筛选；列表保留所属项目、进度和报告入口。即使当前正在某个项目内，Skill 页面也仍展示全团队相关工作。

**开始新任务，再确定所属项目。** 点击 Skill 页右上角的“新建任务”，选择或新建所属项目；当前选中的项目用于新任务和资料上传。点击已有任务或报告，会回到它的原项目；这里的汇总不复制资料，也不生成第二份报告。项目内仍保留上传与整理资料、报告与讨论和协作动态。

每个 Skill 页面先解释解决什么问题、需要哪些输入、如何参考知识库和公开资料、按什么逻辑分析，以及交付物是什么。可以先读说明，再开始任务或打开团队已有成果。

研究边界和行业模板收进“行业知识库 → 某行业 → 研究模板”，项目范围仍可在项目总览调整。同一行业共用分类和比较字段，是为了便于讨论；不要求同事得出相同观点。模板草案、团队确认和实际报告采用的版本分别保留。

## 2. 四个 Skill 怎么选？

| 任务 | 适合什么时候 | 需要提供 | 交付什么 |
| --- | --- | --- | --- |
| Market Research · 行业研究 | 快速了解行业、回答具体问题，或做完整深度研究 | 选择研究目标并填写行业；专题研究另填核心问题，资料和已知公司可选 | 回应目标的核心判断首页、相应深度的正文，以及初步投资框架 |
| Company Mapping · 公司地图与初筛 | 初筛值得继续看的公司 | 行业、筛选条件；已知公司可选 | 候选公司池、重点比较、差异和下一步验证问题 |
| Investment Handbook · 技术投资手册 | 深入理解一家公司的技术 | BP、技术资料、产品信息或访谈纪要 | 投资人能读懂的原理、取舍、行业位置和尽调问题 |
| Evaluation Dashboard · 公司对比 Dashboard | 尽调后持续比较和跟进 | 尽调发现、公司资料和评价框架 | 待审核的比较与评分方案；确认采用后更新共享看板 |

行业研究默认观察**全球、各阶段**公司。填写几个公司名字是提供起点；除非明确限制名单，研究应继续寻找其他代表公司。公司对标以发现 15–25 家候选、重点比较 5–8 家为目标；资料不足时说明缺口，不凑数量。

四个 Skill 的基本逻辑是：

| Skill | 怎样从输入得到结果 | 阅读时要注意 |
| --- | --- | --- |
| 行业研究 | 明确研究目标和行业边界 → 读取相关方法与授权知识 → 按目标搜集公开证据、补齐缺口 → 解释原理与判断依据 → 形成首页、正文和投资框架草案 | 没有公司资料也可以开始；问题研究围绕问题展开，完整研究覆盖全貌；未知数据不编造 |
| Company Mapping | 明确公司筛选范围 → 参考行业分类与已有研究 → 主动发现名单外的公司 → 按同一组字段归类、比较 → 提出重点关注公司与验证问题 | 已知公司是搜索起点；候选池属于初筛，不等于完成尽调 |
| 技术投资手册 | 读取公司资料与相关行业知识 → 对照公开证据 → 拆解原理、技术选择与产品能力 → 说明公司位置和需要访谈验证的问题 | 公司自述、公开验证与平台判断应分开；不能把资料中没有的能力写成事实 |
| 公司对比 Dashboard | 读取尽调发现与既定比较框架 → 对齐指标定义和证据 → 提出比较、评分与待补信息 → 团队审核后更新看板 | 证据不足不强行评分，评分规则和结果不会因一次研究自动覆盖 |

各步骤会按任务范围和现有证据调整。说明是研究设计，不代表每次公开搜索都能取得原文，或最终判断已经通过团队复核。实际使用的资料、方法版本和处理进度可在任务记录核对。

## 3. 按目标开展行业研究

先决定这次要解决什么，再决定报告怎么写。三种目标都可以使用项目资料、授权的团队知识和公开来源；不是只换报告标题。

| 研究目标 | 适合什么时候 | 首页先回答什么 | 正文重点 |
| --- | --- | --- | --- |
| 快速建立认知 | 第一次接触某个行业，希望先看懂全貌 | 行业是什么、解决谁的问题、主要技术分类和行业位置，以及最值得关注的判断 | 通俗解释概念、原理、路线、产业链、代表公司与发展阶段 |
| 回答具体问题 | 已有基础认识，想研究技术壁垒、量产、价值分配等问题 | 先复述这次问题，再直接回答，并给出关键理由、依据和成立条件 | 拆解问题、比较不同解释与证据、展开因果机制和反例；背景只保留理解答案所必需的部分 |
| 完整深度研究 | 需要系统讨论一个行业的机会与风险 | 汇总主要结论、价值集中在哪里、关键技术取舍、发展与商业化判断 | 展开概念、技术原理与路线、产业链和价值链、需求与市场、公司格局、风险和验证清单 |

**三种模式都输出初步投资框架。** 报告应解释这个行业应该重点看哪些能力，例如技术、量产交付、商业化、团队，或对大型竞争者的差异化。维度按行业和公司阶段调整，不把同一张通用评分表套到所有行业。每项应写清：

- 看什么、怎样判断好坏，以及需要什么证据；门槛没有可靠依据时明确写待验证。
- 建议权重和设定理由；同一套完整建议权重合计为 100%，说明适用的行业、业务类型及公司阶段。
- 哪些维度最影响结果，换成更早期或更成熟的公司后是否需要调整；否决性问题单独说明，不能靠其他高分抵消。
- 已有证据、尚缺证据和不确定性。没有资料不等于能力为零，不为了算总分补造数据。

这里的权重是**模型提出、供团队讨论的草案**，不是客观测量结果、投资回报预测，也不会自动成为团队评分标准或覆盖既有 Dashboard。专题研究仍应说明行业框架的适用范围，不能把只验证过一个问题写成完成了全公司评分。团队可在报告中讨论和修订，再决定是否采用。

正文会比过去的短摘要补充更多解释，通常用完整一段讲清“事实是什么 → 为什么会这样 → 对客户或投资判断意味着什么”，配合已有图表。生成时优先写有内容的正文：技术原理、路线取舍、价值链、关键公司案例和投资框架的理由应在正文讲清，不能全部放到附录。方法清单、工具日志和来源目录不计作分析深度；只有证据目录很长，不代表行业已经研究透。证据不足时说明影响与缺口，不用模板文字填篇幅。

新版行业研究的“从模板开始”也沿用所选目标与已填写问题；新模板以分析正文为主，不再附带整套方法卡和重复检查清单。模板占位内容仍需研究后填写。

开始操作：

1. 从固定团队入口进入，选择或新建项目。
2. 如需检查行业边界，进入“行业知识库 → 该行业 → 研究模板”。电子皮肤、RSI、世界模型和灵巧手已有专业分类起点，仍是待校准草案；同一行业复用分类与比较口径，不代表投资权重已经获团队确认。
3. 点击左侧“行业研究”，查看说明或团队已有成果；通过右上角“新建任务”选择所属项目。
4. 选择“快速建立认知”“回答具体问题”或“完整深度研究”，填写行业。选择“回答具体问题”时，必须写清要回答的问题；切换目标不必重新上传资料。
5. 按需补充范围、地域、阶段、截止日和材料。公开检索词只填写可以对外搜索的行业、产品、公司或技术词；内部问题和资料不会因此直接成为公开查询。
6. 提交前查看随目标变化的交付说明。提交后到项目的“报告与讨论”查看进度、耗时和方法使用记录；以后也能从 Skill 的团队任务列表打开。
7. 完成后先检查首页是否回答了本次目标，再看正文依据与投资框架。通过评论讨论，修改后保存新版本。

新任务会保存研究目标与交付策略版本，后续阶段沿用这次任务的计划。已有报告不因此重新生成或改写；新增模式也不会回填成旧任务曾采用的方法。N.E.I. 文件与行业专业框架仍保留各自原来的版本，新交付策略不冒充方法库换版。

阅读页先展示报告内容，把有完整平台标记的检索日志、来源存档和方法读取记录收进文末“研究过程与来源记录”；其中包含来源表时也可折叠。页面分别显示“报告内容”和“平台过程记录”的约计字符数，便于看清长篇内容由什么构成。“报告内容”仍包括作者自己写入的分析和附录，不等于平台已经判定这些文字都有研究价值。

章节目录可返回核心判断首页；有唯一实际来源表记录的 S 编号可点击定位，若出处在折叠区内，会自动展开并跳转。无来源记录的编号不会补造链接。这里仅改变阅读展示，不改写旧报告，不按“附录”标题隐藏作者内容；没有可靠标记的旧记录仍完整显示。已完成或失败任务的过程卡默认折叠，进行中任务优先展示。

下载 Word、Markdown 或打印 PDF 默认保留正文、图表和报告自身的证据附录；只有带完整平台标记、能安全分离的过程记录才折叠或省略，勾选“导出含过程记录”可一并下载。旧报告、标记不完整或分离后会失去引用目标时，自动保留全文。正在编辑时“下载草稿”始终保留完整原文。

图表格式无法解析时，报告顶部会显示数量和首个位置，原始内容仍保留；这项提示只检查格式，不验证事实。F1 图表保留原始 0–1 或已明确标注的 0–100 口径，不自动换算成百分比或准确率。

普通比较表达到六列时，打印和 Word 会按公司或比较对象展开全部字段，避免宽表被裁切；网页仍显示横向比较表。长图表可自然续页，表头重复。较长的历史报告首页可能跨页，不会缩成难以阅读的小字。

研究流程是：**读取框架 → 搜集资料 → 检查缺口并补搜 → 建立认知 → 生成图文报告 → 团队复核**。市场数字没有可靠口径时应解释测算方法或保留未知，不给虚假的精确结果。

## 4. 上传资料与阅读历史报告

新建或打开项目后，从项目下的“上传与整理资料”进入；也可通过 Skill 页的新任务准备入口上传。选择保存到哪个项目，再上传 PDF、Word、PPT、Excel、文字、图片或 ZIP。已有文件也会自动出现在目录里，不会复制或搬动原件。可以按项目、行业和资料类型查找；类型按文件名给出初步建议，可手动修正。

- **单文件最多 256 MB**；每项目 2 GB、500 份文件。本次研究最多选用 20 份原始资料。
- **ZIP 一次上传、逐份解析**，保留压缩包原件和解出的文件。普通 ZIP 最多 500 个条目、解压后合计 512 MB；不递归解压嵌套 ZIP。不支持或失败的文件会单独列出，已成功的文件仍保留。
- **超过 20 MB 的 PDF** 自动按原页序建立读取副本，原件不变；副本必须覆盖全部页面后才用于研究。加密、损坏、单页本身过大等情况会给出提示，不能当作完整读取。
- **大图片**会建立较小的读取副本，保留原图；细小文字和颜色请核对原件。过大的动态 GIF 暂不转换。
- 文字按批次读取，取消原来的 20 万字符总量拦截；任务仍有处理量和调用预算。

过去的团队 PPTX 放在“行业知识库 → 历史研究原件”，也可批量上传含 PPTX 的 ZIP。点击**阅读原文**直接显示页内文字，可搜索和翻页；点击**查看原件图像**读取该页内嵌图片。图片展示不是完整 PowerPoint 排版，复杂图表与字体请下载原件核对。隐藏页、No use / OLD 文件和备注保留归档，但不默认用于研究。

## 5. 文章、检索记录和知识有什么区别？

**行业知识库用来积累下一次研究可以参考的内容。** 历史报告保留团队过去怎么研究、得出了什么判断；公开文章提供可核对的来源；积累的知识整理可复用的事实、方法与待验证观点。主动学习可以补充新的公开资料。它们按行业组织，后续研究在授权范围内检索使用，不需要每次从头整理。保存进去不等于已验证正确，也不等于模型已经学习了全部内容。

**先选行业，再查内容。** 可以搜索电子皮肤、RSI、世界模型等，进入后分为：

- **行业概览：** 展示已有报告的核心判断首页，保留原报告和状态。当前是既有成果的归集，不是新生成的跨报告完整综述；没有可用首页时会明确提示。
- **研究成果：** 这个行业的已有报告，点击即可进入原项目阅读和讨论。
- **积累的知识：** 公开发现、团队确认与待复核内容分开，保留出处。
- **公开资料：** 按行业、渠道和关键词筛选。只有几十字的内容明确标为短片段；“已存文字”不代表取得全文，待补正文链接另列。
- **历史研究原件：** 查找导入的团队报告及其页内原文。
- **研究模板：** 同一行业的定义、技术分类、比较指标和 N.E.I. 方法参考。
- **主动学习：** 保存学习主题、关键词和单次预算，再明确点击“确认并学习一次”发起公开研究。保存主题本身不调用模型。

**日／周学习安排目前只保存为计划草稿，尚未启用自动执行。** 不能仅靠保存时间就期待自动抓取内容。一次学习默认预算上限 40 美元，可调整为 30–80 美元；实际费用取决于模型和处理量。学习计划模块每个团队每天合计最多提交一次，已有任务未结束不重复提交。暂停主题只阻止新提交，不会终止已经启动的任务。提交后会打开项目任务进度；当前请保持该页面打开推进研究。公众号和小红书仅尝试无需登录的公开内容，不能保证拿到正文。

资料目录默认**仅原项目研究可用**。要让其他项目自动参考某份资料，在“整理与权限”中明确允许团队跨项目复用；原件仍留在原项目。模型只检索已提取的文字，并记录文件名、文字位置和版本校验信息；未提取文字的扫描 PDF／图片不会因此自动变成可检索全文。No use／OLD 材料与 ZIP 容器不能开启跨项目复用。内部资料不进入公开搜索词和公开学习任务。

新研究会自动保存来源及实际取得的正文片段，引用链接与内容版本分别保留。可点击“整理历史研究来源”补录以前已完成研究的公开底稿，每次处理 8 个任务；不调用模型，不修改旧报告。底稿中有原文片段才形成文章，只有搜索摘要或链接的仍留在“待补正文”。公开文章、历史报告和团队已采纳方法供后续研究在授权范围内检索与综合，内部材料不进入公开查询；**这是知识检索和方法复用，不是重新训练模型权重**。

研究完成后，会把有出处的公开发现另存为“知识候选”：模型概括、保留的原文片段和限制分开标记，待团队复核后再作为更可靠的共同认知。它不把内部报告搬到公开行业记忆，也不把模型摘录称为已经获取全文。重复整理不会覆盖团队已做的修改。

文章标题、作者或日期更正后会保留新版本，原文内容及旧出处仍可核对。查看旧版本时，不用后来补上的日期填补当时的未知；仅被检索发现、尚未出现在报告中的来源不会标成报告引用。

公众号、小红书优先尝试无需登录的公开内容。搜索标题、摘要、转载和取得原文会区分记录。当前不自动处理登录、验证码或受限页面；公开抓取仅支持允许的网站和 HTML，每次最多保留 50,000 字符，不保存网页图片或视频。其他网站或未取得正文时可补充有权使用的原文、截图或文件。

BP、内部纪要和项目判断默认留在原项目；明确导入团队知识库的历史报告供授权团队跨项目参考。知识候选需要复核，评分规则不会自动覆盖看板。

## 6. 团队怎样一起用？

同事使用同一个固定团队入口，即可看到团队内新项目和已保存的更新，不必反复分享新链接。每个项目的资料、报告、评论和活动记录在云端保存。

- 编辑入口可上传、修改和评论；查看入口只读。当前无需登录，完整链接就是访问凭证。
- 每个团队空间最多加入 100 个项目；重复加入已有项目不会占用新名额，也不会复制资料。
- 报告保存时检查版本，避免覆盖同事的修改；旧版本保留。未保存草稿在本机，不属于逐字实时共同编辑。
- 未发表的评论按项目和报告保存在当前标签页，返回报告可恢复，发表成功才清除对应草稿。离开或刷新会提醒；关闭整个标签页后不保证保留，存储失败会提示先复制。
- 框架、来源和判断有分歧时，在报告中写明对应章节、证据和建议，保留讨论过程。
- 暂无实名成员管理、逐个撤销成员权限和完整的权限审批流程。

## 7. 模型、后台运行与验收

最近核对的模型是 **gpt-6-astra · xhigh**。任务在云端保存，页面展示阶段与耗时；截至本次核对，现有云端接续计划处于暂停状态；请保持任务页面打开推进。日／周学习安排也尚未自动执行。接续间隔不等于报告完成时间；遇到访问限制、调用预算或模型错误，会保留已完成内容并说明问题。此前四行业验收共用 80 美元上限：先预留调用额度，取得实际用量后按标准价加余量计入；无法确认的用量继续占用额度，最终账单以供应商为准。

完整团队历史、文章参考与方法正文的组装保护上限已从 15 万提高至 22 万字符，避免合法的知识库任务在首次调用前被拒绝；这仍是保护上限，不表示所有资料已经由模型读完。

共用费用预算被其他研究步骤预留时，会明确显示等待，直到实际用量确认、额度释放后继续；等待时间计入任务总耗时。

已完成步骤之后会立即尝试衔接下一阶段一次，减少空等一轮调度；仍然不保证网页关闭后连续运行。新请求记录区分请求模型／推理档位与服务商返回的模型名称；旧记录或未返回的字段明确显示未记录。

工作空间设置可查看最近一次经身份验证的云端接续调用时间。它不能区分手动与定时触发，也不代表所有研究均已成功。尚未观察到记录、记录过旧或无法读取，会分别说明。失败任务另有管理员用量核查：只查询已有模型响应、结算已核实的费用，不自动重启或重复付费提交。

第 25 版把已检索的文章与授权研究记忆也送入前置“建立行业认知”，此前它们只进入最终综合。公开发现仍不接收这些内部上下文。已完成旧报告不作追溯性改写，实际提供内容以各次请求记录为准。

任务中的“方法正文与模型调用记录”可以核对实际提供了哪些 Skill、行业方法和版本。选中了文件、正文进入请求、报告正确采用方法，是三件不同的事，不能互相替代。

此前四行业手测目标为电子皮肤、RSI、世界模型、灵巧手，均不上传公司资料。点击左侧“行业研究”，在团队任务中搜索行业或筛选对应的“从零研究验收10.16”项目，再打开原任务或报告；也可以从项目列表进入该项目的“报告与讨论”。项目页上方“研究任务”的“打开”进入自动生成原稿；下方“研究交付物”中的“维护辅助审阅稿（待团队复核）”是独立报告，不在原稿的历史版本里。两者都可能显示 V1，不能只靠版本号区分。

在任务中展开“过程记录 → 方法正文与模型调用记录 → 实际模型请求”，检查“行业认知”和“最终报告”提供的方法文件；此面板不完整展示历史报告、文章和记忆的全部输入。文章库的“查看已存文字”与“待补正文／查看来源记录”分别说明有无已存文本，打开今天的网页不代表模型当时已读。

检查重点：

1. 首页能否在一分钟内讲清行业、主要路线、代表公司和核心判断。
2. 正文是否解释概念、原理、取舍、产业链与市场，而不是堆术语。
3. 是否主动发现海内外公司，来源和日期是否可追溯。
4. 图表是否解释相邻内容，市场规模是否有定义、口径和可靠依据。
5. 来源是否进入文章库；没读到的正文是否如实标记。
